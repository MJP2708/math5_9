# เลขยกกำลังที่มีเลขชี้กำลังเป็นจำนวนตรรกยะ

โครงงานคณิตศาสตร์สร้างสรรค์ (Math Tech Dev.) — วิชาคณิตศาสตร์ 3 (ค32101)
โรงเรียนอัสสัมชัญธนบุรี ระดับชั้นมัธยมศึกษาปีที่ 5

เครื่องมือเว็บแบบอินเทอร์แอกทีฟสำหรับสำรวจค่า **a<sup>m/n</sup>** โดยผู้ใช้ปรับค่าฐาน `a`
และเลขชี้กำลังในรูปเศษส่วน `m/n` ผ่านตัวเลื่อน (slider) แล้วดูกราฟ ผลลัพธ์ตัวเลข
และขั้นตอนการคำนวณแบบละเอียดที่อัปเดตทันทีแบบเรียลไทม์

## เครื่องมือนี้ทำอะไรได้บ้าง

- ปรับค่าฐาน `a` (-10 ถึง 10) และเลขชี้กำลัง `m`, `n` (จำนวนเต็ม) แยกกันด้วยตัวเลื่อน
- ดูกราฟของ f(x) = x<sup>m/n</sup> แบบเรียลไทม์ พร้อมจุดแสดงค่าปัจจุบันที่ x = a
- เมื่อค่าที่เลือกทำให้นิยามไม่ได้ในจำนวนจริง (เช่น ฐานลบยกกำลังเศษส่วนที่มีตัวส่วนคู่)
  กราฟจะแสดงช่วงที่ไม่มีนิยามให้เห็นชัดเจน พร้อมกล่องข้อความอธิบายเหตุผล
- ดูขั้นตอนการคำนวณทีละขั้น เขียนด้วยสัญลักษณ์ทางคณิตศาสตร์ (KaTeX) ตั้งแต่โจทย์ตั้งต้น
  การลดรูปเศษส่วน การถอดราก จนถึงผลลัพธ์สุดท้าย
- เปรียบเทียบกราฟ f(x) = x<sup>m/n</sup> กับ f(x) = x<sup>m</sup> (ยกกำลังอย่างเดียว)
  และ f(x) = <sup>n</sup>√x (ถอดรากอย่างเดียว) เพื่อให้เห็นว่าเลขชี้กำลังที่เป็นเศษส่วน
  แท้จริงแล้วคือการนำสองการกระทำนี้มาประกอบกัน

## หลักการและวิธีคิด (Methodology)

เครื่องมือนี้คำนวณตามนิยามของเลขยกกำลังที่มีเลขชี้กำลังเป็นจำนวนตรรกยะดังนี้ (เรียงตามลำดับการตรวจสอบ):

1. ลดรูปเศษส่วน m/n ให้เป็นเศษส่วนอย่างต่ำก่อนคำนวณเสมอ (เช่น 4/2 จะถูกมองเป็น 2/1)
2. สำหรับ a ≥ 0 และ n > 0: a<sup>m/n</sup> = (<sup>n</sup>√a)<sup>m</sup> = <sup>n</sup>√(a<sup>m</sup>)
   โดยจะถอดรากที่ n ของฐานก่อน แล้วจึงยกกำลัง m ทีหลัง (ไม่ใช่ยกกำลังก่อนแล้วค่อยถอดราก)
   เพื่อความแม่นยำเชิงตัวเลข เพราะการยกกำลังตัวเลขจำนวนมากก่อนอาจทำให้ตัวเลขใหญ่เกินไปจนคลาดเคลื่อน
3. สำหรับ a < 0: จะหารากที่ n ได้จริงในจำนวนจริงก็ต่อเมื่อ n เป็นเลขคี่เท่านั้น
   ถ้า n เป็นเลขคู่ ค่านี้จะไม่มีนิยามในจำนวนจริง
4. เลขชี้กำลังเป็นลบ a<sup>-m/n</sup> = 1 / a<sup>m/n</sup> โดยถ้า a = 0 และเลขชี้กำลังเป็นลบ
   จะไม่มีนิยาม (เทียบเท่าการหารด้วย 0)
5. 0<sup>m/n</sup> เมื่อ m/n > 0 มีค่าเท่ากับ 0 ส่วน 0<sup>0</sup> ถือเป็นรูปแบบไม่กำหนด
   (indeterminate form) ทางคณิตศาสตร์ ไม่ได้มีค่าเท่ากับ 1 เสมอไป

ในการคำนวณจริง ระบบจะพยายามตรวจสอบก่อนว่าผลลัพธ์เป็น **จำนวนสมบูรณ์หรือไม่**
(เช่น 8<sup>2/3</sup> = 4 พอดี) โดยใช้เลขจำนวนเต็มขนาดใหญ่ (BigInt) แทนที่จะใช้ทศนิยมของ
JavaScript ตรง ๆ เพื่อไม่ให้ได้ผลลัพธ์ที่คลาดเคลื่อนเล็กน้อยแบบ 3.9999999999996 แทนที่จะเป็น 4
หากไม่ใช่จำนวนสมบูรณ์ (เช่น 2<sup>1/2</sup>) ระบบจะคำนวณค่าประมาณด้วยความละเอียดสูง
(ผ่านไลบรารี decimal.js) และกำกับด้วยเครื่องหมาย **≈** อย่างชัดเจนเพื่อไม่ให้เข้าใจผิดว่าเป็นค่าที่แท้จริง

### กรณีพิเศษที่เครื่องมือนี้ตรวจจับและอธิบายให้ (ไม่ใช่แสดง NaN หรือค้างจอ)

| กรณี | สิ่งที่เกิดขึ้น |
|---|---|
| ฐานลบ + ตัวส่วนของเลขชี้กำลังเป็นเลขคู่ | แจ้งว่านิยามไม่ได้ในจำนวนจริง พร้อมเหตุผล |
| ฐานเป็น 0 และเลขชี้กำลังเป็นลบ | แจ้งว่าไม่มีนิยาม (เทียบเท่าหารด้วย 0) |
| 0 ยกกำลัง 0 | แจ้งว่าเป็นค่าไม่กำหนด (indeterminate) |
| ผลลัพธ์มีค่ามากหรือน้อยเกินไป | แจ้งเตือนและปรับการแสดงผล แทนที่จะแสดง Infinity ดิบ ๆ |
| พิมพ์เลขที่ไม่ใช่จำนวนเต็มลงในช่อง m หรือ n | แจ้งว่าต้องเป็นจำนวนเต็มเท่านั้น |
| n = 0 | แจ้งว่าตัวส่วนของเลขชี้กำลังเป็น 0 ไม่ได้ |

## เทคโนโลยีที่ใช้

- Vite + React + TypeScript
- Tailwind CSS
- Plotly.js (ผ่าน react-plotly.js) สำหรับกราฟแบบเรียลไทม์
- KaTeX (ผ่าน react-katex) สำหรับแสดงสัญลักษณ์ทางคณิตศาสตร์
- decimal.js สำหรับการคำนวณทศนิยมความละเอียดสูง และ BigInt ของ JavaScript
  สำหรับตรวจสอบผลลัพธ์ที่เป็นจำนวนสมบูรณ์แบบแม่นยำ 100%

ตรรกะการคำนวณหลักทั้งหมดอยู่ที่ `src/lib/rationalExponent.ts` และมีชุดทดสอบ (unit test)
ครอบคลุมทุกกรณีที่ `src/lib/rationalExponent.test.ts`

## วิธีติดตั้งและรัน

ต้องมี [Node.js](https://nodejs.org/) ติดตั้งไว้ก่อน จากนั้นรันคำสั่งต่อไปนี้ในโฟลเดอร์โปรเจกต์:

```bash
npm install
npm run dev
```

แล้วเปิดลิงก์ที่ปรากฏในเทอร์มินัล (ปกติคือ http://localhost:5173) ด้วยเบราว์เซอร์

### คำสั่งอื่น ๆ ที่ใช้ได้

```bash
npm run build   # ตรวจสอบชนิดข้อมูล (TypeScript) และสร้างไฟล์สำหรับเผยแพร่ในโฟลเดอร์ dist/
npm run test    # รันชุดทดสอบตรรกะการคำนวณทั้งหมด
npm run preview # เปิดดูไฟล์ที่ build แล้วในเครื่อง
```

โปรเจกต์นี้ทำงานฝั่งไคลเอนต์ทั้งหมด ไม่มีเซิร์ฟเวอร์หรือฐานข้อมูล
